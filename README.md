# Mud Terrain Simulator

محاكي قيادة على طرق وعرة موحلة، مع لوحة إدارة كاملة — يعمل في المتصفّح ويُغلَّف
كتطبيق سطح مكتب لويندوز/ماك/لينكس.

المشروع مستقل بالكامل: لا يحتاج إنترنت ولا خدمات خارجية وقت التشغيل. الخامات
الأرضية وصور الأجزاء تُولَّد إجرائيًا داخل التطبيق، والملف الخارجي الوحيد هو
موديل المركبة.

---

## التشغيل السريع

```bash
npm install
npm run dev          # http://127.0.0.1:5173
```

**التحكّم — داخل المركبة:** `W A S D` للقيادة · `Space` مكابح اليد ·
`F` للنزول · `R` إعادة المركبة

**التحكّم — على الأقدام:** `W A S D` للمشي · `Shift` جري · `Space` قفز ·
`F` للركوب (لازم تكون قريب من باب السائق)

اسحب بالفأرة لتدوير الكاميرا · عجلة الفأرة للتقريب.

المحاكاة متوقّفة عند الإقلاع — اضغط **«بدء المحاكاة»**.

## نسخة الكمبيوتر (‎.exe‎)

### الطريقة الأسهل — بدون تثبيت أي شيء

ادخل تبويب **Actions** في الريبو على GitHub ← **Build desktop app** ←
**Run workflow**. بعد دقائق تنزل المثبّتات جاهزة من قسم Artifacts:
ويندوز `.exe` وماك `.dmg` ولينكس `.AppImage`.

ولو دفعت وسمًا يبدأ بـ `v` (مثل `v0.1.0`) تُرفَع تلقائيًا في Releases.

### أو ابنِها بنفسك

```bash
npm i -D electron electron-builder
npm run desktop:win      # ويندوز 64-bit → مجلد release/
npm run desktop:build    # للمنصّة الحالية
```

`electron/main.cjs` يحمّل الحزمة المبنية من القرص مباشرة — لا خادم ولا شبكة.
مُختبَر فعليًا: التطبيق يُقلع من `file://` ويحمّل الموديل (19 ميجا) وفيزياء
Rapier بلا أي خادم — حجم النسخة النهائية حوالي 110 ميجا.

للتحقّق من نسخة سطح المكتب آليًا:

```bash
node scripts/desktop-smoke.mjs shot.png
```

### حقل الطين (MudField)

سطح القيادة يُحسب كالتالي:

```
surfaceY(x,z) = baseHeight(x,z) - depth(x,z) + ridge(x,z)
```

- `depth` — كم انضغطت التربة للأسفل
- `ridge` — الطين المُزاح جانبًا والمتكوّم على حافّة الأخدود

**نفس الحقل يقرأه العرض والفيزياء**، فالأخدود الذي تحفره الآن هو الأخدود الذي
ستضطر للخروج منه بعد قليل. البيانات تُرفع للـ GPU كتكستشر RGBA واحد، ولا يُرسل
منه إلا المستطيل الذي تغيّر فعلًا في كل إطار.

الغوص مُعايَر على مرجع حقيقي: إطار شاحنة محمّل يضع ~40 كيلوباسكال على مساحة
التماس، و40 كيلوباسكال على أرض مُشبعة بالماء تغوص ~25 سم.

### فيزياء المركبة

Rapier يملك جسم الهيكل فقط؛ العجلات ليست أجسامًا فيزيائية — كل عجلة تُسقط شعاعًا
تحليليًا على حقل الطين. في كل خطوة فرعية (120 هرتز):

1. تحديد نقطة التماس على سطح الطين
2. نابض + مخمّد ← الحمل العمودي
3. دمج دوران العجلة مع عزم المحرك والفرامل
4. **نموذج إطار قائم على الاندفاع** — يحسب القوة اللازمة لتصفير الانزلاق خلال
   الخطوة ثم يقصّها على دائرة الاحتكاك. مستقر عدديًا عند أي سرعة، بخلاف نموذج
   منحنى الانزلاق الذي ينفجر قرب السكون
5. مقاومة الدحرجة من شقّ الطين، متناسبة مع عمق الغوص
6. ختم مساحة التماس في حقل الطين

ناقل حركة أوتوماتيكي بخمس سرعات، منحنى عزم واقعي لمحرك V6 سعة 4.0 لتر، قضبان
مانعة للميلان، ودفع رباعي.

> **ملاحظة مهمّة لمن يعدّل الفيزياء:** القوى في Rapier **تبقى فعّالة عبر كل
> الخطوات** حتى تُصفَّر يدويًا، عكس أغلب المحرّكات. لذلك `Vehicle.step()` يبدأ
> بـ `resetForces()` — بدونها تتحوّل قوة تعليق واحدة إلى صاروخ دائم.

### اللاعب على الأقدام

الشخصية **حركية (kinematic)** بالتصميم: تُحسب يدويًا على نفس حقل الطين الذي
تقرأه عجلات المركبة، بدل أن تكون جسمًا في Rapier. هذا يبقي **مصدرًا واحدًا
للحقيقة** عن الأرض — تمثيل تصادم ثانٍ كان سينحرف عن الطين المتشوّه — ويجعل
المنحدرات والدرجات والالتصاق بالأرض بسيطة على حقل ارتفاعات.

- مشي 2.3 م/ث · جري 5.8 م/ث · قفز بذروة 1.05 م
- **الطين العميق يبطّئك** ويجعلك تخوض بدل أن تجري
- المنحدرات الأشدّ من 52° تُزحلقك
- مهلة سماح (coyote time) 0.12 ث بعد مغادرة الحافة
- الشاحنة صندوق مصمت — لا تمشي داخلها

المجسّم **إجرائي بالكامل** (جذع وأطراف تتحرّك بدورة مشي حقيقية)، فالنظام يعمل
بدون أي أصول. ولو حطّيت `public/models/character.glb` — تصدير Mixamo يكفي —
يتولّى مكانه تلقائيًا، وتُشغَّل مقاطعه حسب حالة الحركة (idle / walk / run / jump).

### توليد التكشير بالذكاء الاصطناعي

اللوحة تولّد خامات البلى محليًا وبشكل حتمي (نفس الوصف + نفس البذرة = نفس النتيجة)،
وتقرأ كلمات مفتاحية عربية وإنجليزية: صدأ، طين، خدوش، مبلل، والألوان.

لتوصيلها بنموذج توليد صور حقيقي، اضبط متغيّر البيئة:

```bash
VITE_TEXTURE_API=https://your-service/generate
```

الخدمة تستقبل `{prompt, part, seed}` وتُرجع `{image: "<data|http url>"}`. باقي
اللوحة لا يتغيّر. إن فشل الطلب يعود التطبيق تلقائيًا للتوليد المحلي.

اختيار أي نتيجة يطبّقها فورًا على الجزء المقابل في المشهد ثلاثي الأبعاد.

خادم توليد حقيقي جاهز في `server/texture-service.mjs` بمحوّلات لـ ComfyUI محليًا
أو Replicate أو أي واجهة متوافقة مع OpenAI:

```bash
npm run texture-service     # افتراضيًا بدون مزوّد: يرجع للتوليد المحلي
npm run dev:all             # الخادم + الواجهة معًا
```

### من الصورة إلى خامة

ارفع صورة من جوالك لباب أو حائط أو أرض، حدّد زواياها الأربع، والنظام:
تصحيح منظور ← موازنة أبيض ← **إزالة الإضاءة المخبوزة** ← تبليط بلا حواف ←
اشتقاق خرائط normal / roughness / AO / height.

إزالة الإضاءة هي الخطوة الحاسمة: صورتك تحمل شمس اليوم الذي صوّرت فيه، وإزالتها
هي ما يجعل الخامة تتلوّن بإضاءة اللعبة. مُقاسة على مشهد اختبار: تدرّج شمس بنسبة
2.79× بين زاويتَي الصورة نزل إلى 1.05× بعد المعالجة.

**الدليل الكامل مع إرشادات التصوير الصحيح: [`docs/PHOTO_PIPELINE.md`](docs/PHOTO_PIPELINE.md)**

## أدوات الفحص

المشروع يشتغل ويُختبر بلا واجهة رسومية عبر Chromium (‎SwiftShader‎)، ما يجعل
التحقّق من التعديلات آليًا:

```bash
node scripts/shot.mjs --url "http://127.0.0.1:5173/?quality=low" \
                      --out shot.png --physdrive 8
node scripts/diag.mjs          # حالة الكاميرا والتضاريس والمركبة
node scripts/traj.mjs          # مسار المركبة خطوة بخطوة (لتشخيص الفيزياء)
node scripts/debugmodes.mjs    # تصوير قنوات شيدر الأرض واحدة واحدة
node scripts/shadersrc.mjs     # إفراغ الشيدر المُجمَّع للتأكّد من الحقن
```

`?quality=low` يخفّض كثافة الشبكة والظلال ليعمل التصيير البرمجي بسرعة معقولة.

الشيدر يدعم وضع فحص القنوات مباشرة من الكونسول:

```js
sim.terrain.debugMode = 1   // 1=الميل 2=التعكّر 3=العمق 4..9=الخامات والنورمال
```

## الأصول والحقوق

- موديل المركبة: `public/models/frontier.glb` (رفعه المستخدم). **قبل أي نشر
  تجاري تأكّد من ترخيص الموديل** — استخدام علامات سيارات حقيقية يحتاج إذنًا من
  الشركة المصنّعة.
- كل ما عدا ذلك — التضاريس، الخامات، الصخور، الأشجار، أيقونات الواجهة —
  مُولَّد بالكود داخل هذا المستودع.

## القيود الحالية

- عالم واحد بمساحة 220×220 م (بدون تحميل تدريجي)
- `vehicleCatalog.ts` جاهز ببيانات أربع مركبات لكنه **غير موصول** بعد —
  `Vehicle.ts` ما زال يثبّت مواصفات الفرونتير في الكود
- زرّ «تطبيق على الأرض» في استوديو الصور يستبدل خامة واحدة من الأربع (التراب
  افتراضيًا)، لا يرسم على بقعة محدّدة
- الشخصية تصطدم بالمركبة والأرض فقط (ليس بالصخور والأشجار بعد)
- الأضرار تُحسب كنسبة عامة، بدون تشوّه هندسي للهيكل
- لا يوجد صوت
